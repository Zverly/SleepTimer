# 睡前定时关机软件设计

## 1. 项目目标

为 Windows 10 和 Windows 11 制作一款适合睡前使用的定时关机软件。用户应当只用鼠标便能快速选择常用时长、启动任务、延长时间或取消任务。产品强调低干扰、可靠、安全和离线运行，不发展成复杂的计划任务或电脑管理工具。

## 2. 调研结论

设计参考了以下同类项目和产品：

- Shutdown Timer Classic：关机、睡眠、休眠、托盘后台、阻止提前睡眠、彩色倒计时和正常/强制模式。
- Shutdowner for Windows：暗色界面、大号数字、鼠标滚轮设置时间和暂停/继续。
- Portable Windows Shutdown Timer：软件关闭后任务仍然有效，并支持增加时间和取消任务。
- Wise Auto Shutdown：倒计时、指定时间、提前提醒和一键延后。
- Shutdown PC Timer：大号倒计时、托盘运行、10 分钟和 1 分钟提醒。
- GNOME ShutdownTimer：将定时器放进系统快捷入口，并使用系统级任务提高可靠性。

现有软件大多偏向功能罗列或精细时间输入，缺少专门面向睡前场景的一键预设。首版因此采用“预设优先、两次点击启动”的核心交互。

## 3. 范围

### 3.1 首版包含

- Windows 10/11 x64。
- 正常关机和睡眠两种快捷动作。
- 强制关机高级选项。
- `30分钟`、`1小时`、`1.5小时`、`2小时`四个可编辑预设。
- 指定当天或次日具体时间。
- 托盘后台运行。
- 取消、增加 30 分钟和减少 30 分钟。
- 剩余 10 分钟、1 分钟和 30 秒提醒。
- 深色、低亮度、纯鼠标可操作界面。
- 便携版和后续可选安装包。

### 3.2 首版不包含

- 自动降低系统音量。
- 每日或每周循环任务。
- 多任务并行。
- 家长控制、程序限制、使用日志分析。
- 联网、广告、遥测、账户和自动更新。
- 非 Windows 平台。

## 4. 技术方案

采用 C#、.NET 和 WPF。WPF 负责桌面界面，Windows 自带任务计划程序负责最终动作。应用以 x64 便携形式发布，避免依赖 Web 运行时或复杂安装框架。

使用 Windows 任务计划程序而不是只在界面进程中倒计时，确保窗口关闭或应用意外退出后任务仍然存在。所有任务使用固定、可识别的应用命名空间，应用只读取和修改自己创建的任务。

正常关机在目标时刻调用不带强制参数的 Windows 关机路径，让未保存文件有机会阻止关机。强制关机使用独立路径并显著提示数据丢失风险。睡眠动作由应用内的电源执行入口调用 Windows 原生接口。

## 5. 组件划分

### 5.1 应用外壳

负责单实例启动、窗口生命周期、导航和全局状态。第二次启动时激活现有窗口，不创建第二个计时任务。

### 5.2 首页与计时页面

首页展示电源动作、四个预设、指定时间入口和开始按钮。计时页面展示大号剩余时间，以及增加 30 分钟、减少 30 分钟、取消任务和隐藏到托盘四个主要操作。

### 5.3 任务调度服务

负责创建、读取、替换和删除应用自己的 Windows 单次任务。任意时刻最多存在一个有效任务。修改时间时先确认新任务可以创建，再以可恢复方式替换旧任务，避免出现没有任务或重复任务的中间状态。

### 5.4 电源操作服务

将正常关机、强制关机和睡眠封装为明确的独立动作。界面和调度服务不直接拼接系统命令。自动测试使用同一接口的安全替身，不执行真实电源操作。

### 5.5 托盘服务

显示当前动作和剩余时间，提供显示主窗口、增加或减少 30 分钟、取消任务、打开设置、“退出并保留计划”和“退出并取消计划”。关闭主窗口只隐藏到托盘，不取消任务。

### 5.6 提醒服务

在应用运行时发出 10 分钟和 1 分钟托盘通知。剩余 30 秒时显示置顶小窗口，提供取消和调整 30 分钟。提醒默认不播放声音。

### 5.7 设置与状态存储

预设、主题、上次动作、上次预设和当前任务摘要保存在程序目录下的 `data` 文件夹。使用临时文件加原子替换写入，避免中途断电造成半写文件。配置损坏时保留备份并恢复默认值。

## 6. 用户流程

1. 首次启动默认选择“关机”和“1小时”；后续启动恢复上次选择。
2. 用户点击动作与预设，再点击“开始倒计时”。
3. 应用校验目标时间并创建 Windows 单次任务。
4. 系统任务创建成功后，界面才进入计时状态。
5. 用户可以增加或减少 30 分钟、取消或隐藏到托盘。
6. 修改任务时应用替换系统任务并更新本地摘要。
7. 到点前按规则提醒；到点后系统任务执行对应电源动作。
8. 再次启动应用时，以 Windows 任务状态为准恢复界面，不能仅相信本地摘要。

指定时间早于或等于当前时间时，界面明确显示任务将安排到次日，用户确认后才能开始。

## 7. 睡眠与唤醒规则

- 关机任务允许唤醒已经睡眠的电脑并完成关机。
- 睡眠任务不唤醒电脑；电脑已经睡眠时无需重复执行。
- 使用电池时仍可执行用户明确创建的正常关机任务。
- 应用不会因为使用电池而自动升级为强制关机。

## 8. 安全与异常处理

- 创建系统任务失败时不显示计时成功，保留用户输入并给出可操作的重试信息。
- 取消或延时失败时继续显示真实的当前任务，不能假装操作成功。
- 正常关机被未保存文件阻止时，不自动执行强制关机。
- 首次启用强制关机需要风险确认；每次创建强制任务都显示风险标记。
- 系统时间或时区变化后重新读取实际任务时间，并在界面展示最终执行时刻。
- 应用不搜索、取消或覆盖其他软件创建的关机任务。
- 配置损坏时将原文件重命名为备份并恢复默认设置。
- 日志不记录用户文档、窗口标题或其他隐私内容，只记录应用任务状态和错误代码。

## 9. 界面设计

首页采用已确认的“预设优先”布局：

- 顶部是关机/睡眠分段选择。
- 中部是两行两列的大号预设按钮。
- 下方提供较弱层级的“指定时间”入口。
- 底部是唯一的主操作按钮“开始倒计时”。
- 使用暗色背景、低饱和强调色、充足点击区域和清晰选中态。
- 启动任务需要选择预设和点击开始两步，防止误触立即执行。

计时页面以剩余时间为视觉中心。取消按钮与延时按钮保持明显区分，强制关机状态使用警示色但不使用持续闪烁动画。

## 10. 测试策略

### 10.1 自动测试

- 四个默认预设及自定义预设读写。
- 指定时间跨午夜计算。
- 单任务创建、替换、取消和延时。
- 系统时间及时区变化后的状态恢复。
- 配置原子写入、损坏备份和默认恢复。
- 正常关机与强制关机命令路径严格隔离。
- 非本应用任务不会被修改。
- 单实例与重复启动恢复。

自动测试统一注入假的任务调度器和电源执行器，不允许执行真实关机或睡眠。

### 10.2 Windows 集成测试

- 创建、读取和删除真实的应用测试任务。
- 测试任务的最终动作只写入 E 盘测试记录，不执行电源操作。
- 验证应用退出后测试任务仍存在。
- 验证重新打开应用能从系统任务恢复状态。
- 验证唤醒标记只应用于关机任务。

### 10.3 人工验收

- 全流程只使用鼠标完成。
- 主窗口关闭、托盘恢复、延时和取消。
- 10 分钟、1 分钟及 30 秒提醒。
- Windows 10 和 Windows 11。
- 100%、125%、150% 和 200% 显示缩放。
- 普通用户权限和任务计划程序不可用时的错误提示。

真实关机和睡眠只在人工验收的最后阶段执行，并在测试前保存所有文件。

## 11. 构建与交付

- 源码、依赖缓存、测试输出和发布产物均放在 E 盘项目目录。
- 首先交付自包含的 Windows x64 便携目录和 ZIP。
- 配置、日志和状态保存在便携目录的子文件夹内。
- 便携版稳定后制作可选安装包，默认建议 E 盘路径并允许修改。
- 发布前检查产物不写入 C 盘应用数据目录，不包含开发日志和测试任务。

## 12. 验收标准

- 新用户能在不使用键盘的情况下，于三次点击内创建常用关机任务。
- 窗口关闭或应用意外退出后，已创建的系统任务仍有效。
- 应用重新打开后能准确恢复系统中的当前任务。
- 正常关机不会在未获用户同意时变成强制关机。
- 取消和延时操作以 Windows 中的真实任务状态为最终依据。
- 软件完全离线，不收集数据，运行时保持低资源占用。
